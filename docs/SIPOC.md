# SIPOC｜旅行社獲客網站流程規格

版本：v0.2｜日期：2026-10-19｜狀態：規劃完成，尚未開發

上游需求見 [CCI](CCI.md)，功能與驗收見 [PRD](PRD.md)。第一版是本地模擬的前端教學網站。

## 流程起訖

起點：研究員整理上午資料，企劃人員建立明確標示的模擬行程。

終點：旅客看完推薦與比較，產生、複製或下載諮詢需求單。網站不自動收件、不將資料送給業務。

## SIPOC 總表

| Suppliers 供應者 | Inputs 輸入 | Process 處理流程 | Outputs 輸出 | Customers 接收者 |
|---|---|---|---|---|
| 觀光署、官方活動網站及原資料提供單位 | 景點名稱、地區、特色、官方活動期間、來源與查詢日 | 研究員整理並保留來源，辨識缺漏及過期資訊 | 既有研究檔與來源紀錄 | 旅遊企劃及教材編製者 |
| 教學企劃人員，日後可由旅行社提供真實商品 | 模擬方案、示範價、示範天數、風格標籤、示範每日提綱與研究 ID | 在獨立本地資料規格中組成教學商品，標記所有模擬欄位 | 可供規則推薦的模擬行程清單 | 網站前端 |
| 旅客：親子、情侶、熟齡 | 旅伴、預算、天數、風格及選填出發日 | 驗證輸入、硬性篩選、風格比對、穩定排序 | 最多 3 筆模擬推薦及理由 | 旅客 |
| 旅客與推薦結果 | 比較選擇、限制及來源 | 最多 3 筆比較，確認欲詢問的候選 | 可比較的行程資訊 | 旅客 |
| 旅客的明確操作 | 已確認偏好、1–3 筆候選、選填需求備註 | 本機組合需求單，提供複製或下載 | 標示模擬且「尚未傳送」的需求單 | 旅客；旅客日後自行交給旅行社業務 |

觀光署提供旅遊情報，不提供本版的模擬售價、套裝商品或服務承諾。活動主辦者的公告期間不等同於每日演出安排。

## 交接步驟與品質控制

| 步驟 | 輸入與來源 | 網站／人工行為 | 交付與檢查 |
|---|---|---|---|
| P01 準備資料 | 上午研究、來源紀錄、週報 | 人工選取研究 ID，定義獨立模擬方案。 | 真實研究不覆寫；模擬資料都有標記，缺漏不補猜。 |
| P02 選擇需求 | 旅客四項核心選擇 | 前端檢查必填、合法預算、天數及風格。 | 有效需求快照；錯誤就停在欄位，不產生假結果。 |
| P03 比對方案 | 需求快照＋本地模擬行程 | 旅伴、預算、天數硬篩選，風格至少符合一項，再處理日期限制。 | 符合條件清單；不自動放寬條件。 |
| P04 生成推薦 | 合格清單 | 按風格符合數、示範價格、ID 排序，最多取 3 筆。 | 以固定模板組合推薦理由，不呼叫外部 AI。 |
| P05 比較與選擇 | 推薦結果與旅客操作 | 顯示統一欄位，保留模擬標示與限制。 | 最多 3 筆比較及 1–3 筆諮詢候選。 |
| P06 建立需求單 | 同一份需求快照＋選中候選 | 本機組合純文字，旅客主動複製／下載。 | 顯示「需求單已產生，尚未傳送給旅行社」。 |
| P07 後續人工服務 | 旅客自行提供的需求單 | 業務另查實際價格、營運、交通與服務條件。 | 正式行程及報價屬後續工作，本版不宣稱已完成。 |

## 異常交接

- 缺少四項必填：指出欄位，不進入推薦。
- 本地資料讀取失敗：顯示重試；讀不到不偷偷替換成臨時資料。
- 個別模擬方案無有效價格或天數：排除該筆並記錄問題，不當作 0 元或 1 天。
- 沒有符合方案：顯示空狀態，讓旅客主動修改條件。
- 日期限制不足：未填出發日不推薦限定活動；期間符合仍提醒場次待確認。
- 偏好修改：舊結果與需求單失效，重新推薦後才能再匯出。
- 複製失敗：提供手動選取及下載，不顯示假成功。
- 外部聯絡未串接：停在需求單，不顯示「已寄出」「業務已收到」或虛構聯絡資訊。

## 第一版責任與隱私界線

所有運算在前端完成，使用本地模擬資料，不使用 Supabase、帳密系統或付費 API。不收姓名、電話、Email、證件或付款資料，不將偏好寫到網址、永久儲存或外部服務。自由文字提醒不要輸入個資。

只要旅客沒有主動複製或下載，需求內容就留在頁面記憶體；重新整理或按清除即重設。官方來源連結由旅客自行點擊開啟，與「網站自動送出需求」不同。

## 課堂檢查

請學員沿著一筆模擬方案逐步指出：誰提供景點事實、誰設計示範價、四項偏好如何影響結果、哪個按鈕只在本機運作，以及業務何時才真正收到內容。回答不清楚時，先回到 PRD 修改規格，不直接追加程式。
